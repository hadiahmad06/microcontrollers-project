## Findings
1. **MEDIUM, `c2_stream.h:93,104` (and `.c:136,149`)**: the spec signature `const int16_t (*)[3]` makes the natural caller `int16_t buf[150][3]` emit `-Wpedantic` "invalid use of pointers to arrays with different qualifiers in ISO C before C2X" (reproduced with gcc 13 `-std=c99 -pedantic -Wall -Wextra`; `-Werror` makes it a build break). Every caller (capture buffer, bring-up path) needs a cast. Fix (pick one): (a) document the cast and add `#define C2_ROWS(p) ((const int16_t (*)[3])(p))`; or (b, preferred) change the two parameters to `const int16_t *rows` (row-major, 450 / 48 values), which removes the cast in `frame_byte` and enables F3. This changes a spec signature, so the main agent decides; the tests pass 2-D arrays and would need a cast or the same change.
2. **LOW, `c2_stream.c:176-186`**: empty text returns true and stays idle. Spec says "accepts" and nothing is sent, so it is consistent; `c2_tx_busy` is false right after. Keep; the header comment already says so. No fix.
3. **LOW (perf and flash), `c2_stream.c:197-263`**: per byte the pump calls `frame_byte` (switch, `head_len`, `payload_len`, `/3`) and a 1-byte `c2_crc16_update(&b)` (address-taken local forces a stack store). Estimate on PIC24 at 16 MIPS (XC16 -O1, not measured, no toolchain here): `e / 3u` is `repeat #17; div.u` = 18 cycles (C7 table: DIV 18); the rest of `frame_byte` about 25; the CRC call plus two nibble steps about 35; pump loop about 12. About 90 to 110 cycles per byte, so one 32-byte pump is about 3.2k cycles = 0.2 ms; a full 922 B WINDOW is about 92k cycles = 5.8 ms CPU against 80 ms on the wire (922 x 86.8 us), about 7%. This does not threaten the 50 ms PC-side backstop: that is an inter-byte gap on the wire and a 0.2 ms call is 250 times smaller. What matters is how often the main loop reaches the pump: the C7 TX ring is 128 B = 11 ms of wire time, so each main-loop pass (classify, features, I2C drain included) must stay under about 11 ms between pump calls or the line idles mid-frame; a mid-frame gap above 50 ms makes the PC decoder drop a byte. Record that loop-period requirement in the UART-driver ticket. Optional fix, which also shrinks code: put the 6 header bytes into `head[]` at start (RAM +6 B, about 34 B on avr, still under 40), drop `head_len`/`payload_len`/the switch, index samples flat (`((const int16_t *)src)[e]`, no `/3`, needs F1(b)), and CRC a whole run once (`c2_crc16_update(crc, out + start, count)`) instead of per byte. Expected about 35 to 45 cycles per byte (about 2.5% CPU) and the 854 B `c2_tx_pump` on avr roughly halves.
4. **LOW (flash), C7 line "UART driver + raw stream" 1,500 B**: avr .text of `c2_stream.o` is 1656 B at -O1 and 1336 B at -Os (pump 854 B at -O1, CRC 126 B, table 32 B). avr is 8-bit, so 16-bit math costs about 2 instructions per op; PIC24 is 16-bit native at 3 B per instruction, so my guess is about 0.9 to 1.4 KB (UNVERIFIED until built with XC16). That leaves roughly 100 to 600 B of the 1,500 B for the UART driver: tight, but the C7 total is 21.9 KB of 65.3 KB (33.5%), so an overrun of a few hundred bytes on this line is not a budget risk. Not a blocker. Cheapest shrink is F3; `-Os` alone saves about 320 B on avr.
5. **LOW, `c2_stream.c:236-257`**: release is a single flag. If a second WINDOW ends before `c2_tx_take_release`, one `true` is lost (tester's noted ambiguity). The buffer rule already forbids reuse before the first release, so it is harmless. Add one sentence to the `c2_tx_take_release` doc: "calls are not counted; take the release before starting the next WINDOW". Behaviour unchanged.
6. **LOW, test strictness (tester's notes)**: the suite pins the chunk size to exactly `min(room, 32, remaining)`. The spec says "up to", so a correct implementation returning fewer bytes would fail. This pins the real behaviour and is acceptable; note it in `firmware/test/c2_stream/oracle.py` as a deliberate over-constraint. Shared SEQ across HELLO/WINDOW/SAMPLES matches S6 ("frame counter"); text takes none, which the suite asserts. The `out == NULL` guard returns 0 and is correct.
7. **INFO**: SEQ stored as next (`seq - 1` on output) is correct and tested. `c2_tx_init(NULL)` and `c2_tx_window_id(NULL)` return quietly; fine.
