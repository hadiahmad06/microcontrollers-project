## Findings

1. **HIGH, tools/recorder.py:713-724 (`StreamRecorder.write`) and tools/cut_stream.py:204-215 (`save`): fake marks can become
   real-looking training data.** `--marks-from` replaces the wall-clock marks, but `synthetic` is written only if the user also passes
   `--synthetic`; `meta.marks_from` is recorded but `cut_stream` never looks at it. A real recording cut with a stray marks file
   yields `synthetic=0` labels. Fix: in `StreamRecorder.write` force `synthetic = 1` whenever `self.marks_from is not None` (and print a
   stderr line `--marks-from is TEST ONLY; output marked SYNTHETIC` at start); in `cut_stream.main`, if `meta.marks_from` is set,
   also force synthetic=1 and warn. Help text and RECORDING.md say "test only"; nothing enforces it. Add a test: input without
   `--synthetic` plus `--marks-from` gives synthetic 1. Judgement of the deviation: acceptable only with this enforcement.

2. **MEDIUM, tools/recorder.py:626-650 (`tick`): GO marks are written when no data is flowing.** With `--no-pause`, or when the
   wand stalls or is unplugged, GOs keep printing and marks pile up at the same sample index (all at 0 before the first HELLO). The
   user performs gestures that are never recorded and the summary looks normal. Fix: do not advance GOs while `self.hello is None`
   or no chunk arrived in the last ~1 s; print `waiting for wand` instead (track `self.last_rx = time.monotonic()` in `on_frame`).

3. **MEDIUM, recorder.py:648 (mark index) vs cut_stream.py `label_window`: mark index runs early by about 0.2 to 0.3 s.** `rec.m` is
   the newest stored sample, but a sample is up to 160 ms old when its chunk is sent, plus serial latency. The mark sits earlier in the
   stream than the moment the user saw GO, so `trigger - mark` is inflated by about 0.2 s and the effective late limit is about
   1.8 s of real reaction. Not a bug at the 2.0 s default, but note it in RECORDING.md or add a constant `MARK_LAG = 16` samples.

4. **LOW, defaults (2.0 s window, 1.0 s none-gap, GO every 2.5 s): sensible, with traps to document.**
   - Late person: a trigger up to 2.0 s after GO gets that GO's label; 2.0 to 2.5 s is dropped as ambiguous; later than 2.5 s is
     silently labelled with the NEXT GO. Early person (anticipating the cadence): a trigger 1.5 to 2.0 s after GO k is labelled k
     although it may be gesture k+1 done 0.5 s early. A 1.5 s limit would shrink that hazard at little cost (typical reaction under
     1 s); suggest default 1.5 or document it.
   - A gesture step has no mark-free 1 s, so `none` windows come only from `none:N` steps and from pauses between steps (readying
     motion before the first GO becomes `none`; the hand returning within 2.0 s after the last GO is labelled as that gesture). Tell the
     user to keep the hand still during the Enter pause. The "multi" column catches double triggers (dead time 135+30 = 165 samples).

5. **LOW, recorder.py:664-679 and cut_stream.py `cut`: gaps and wrap are right; OVR is approximate.** `chunk_gaps` stores the first sample
   after the gap, `find_triggers` resyncs before it, wrap handled by `& 0xFFFF`. Marks use the stored index so they stay aligned with
   data after lost chunks (the stream just gets shorter than wall time). A duplicated or reordered chunk records `lost = 65535`
   (harmless). OVR is placed where the text line is decoded, up to one chunk (16 samples) from the true discontinuity, so a
   window with a hidden discontinuity near its edge could survive. Fix: drop windows whose span meets `[ovr-16, ovr]`, or document it.
   Judgement of "windows spanning a gap/OVR are dropped": correct and conservative; the test `t-15 < g < t+135` is right.
