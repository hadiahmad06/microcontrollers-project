## What I checked and found correct

1. **Integer ranges.** `x - (base >> S)` uses int32 on all paths; |dev| <= 4095, L1 <= 12285 (fits int16 as the proposal says), EMA-MAX <= 4095, MAG2 sum <= 12 582 912 (24 bits) and its scaled threshold 12285 x 1024 = 12 579 840 fit int32. `(uint32_t)mg + 1u` is computed in 32 bits, so `mg = 65535` does not wrap (-> 12285). All counters are `uint8_t` with explicit saturation (`warm_n < 255u`); promotions to 16-bit `int` are harmless. Every expression with a different result under a 16-bit `int` was inspected: none. `avr-gcc -mmcu=atmega2560 -std=c99 -Wall -Wextra -Wconversion -Werror -O1 -c trigger.c` builds clean. The host C was also run under UBSan + ASan (`-fno-sanitize-recover=all`) on 16 streams of full-scale +-2048 values over all four statistics and shifts 1, 3, 4, 8: no report, and the per-sample hash is identical to the Python mirror on all 16. (The atmega2560 build is a compile-only proxy for the PIC24 `int`; nothing ran with 16-bit int.)
2. **C versus Python.** `compare` runs 400 streams (40 seeds x 10 kinds, config, threshold, release delay, resync point all varied) through the compiled `trigger_cli` (separate process) and the Python mirror and compares trigger indices and an FNV hash of the per-sample state: 156 triggers, identical. The test is genuinely two runs. Weakness: the same author wrote both, and the generator never produces full-scale values; my 16 extreme streams cover that gap. `synth.py` is described honestly ("UNVERIFIED: every shape and amplitude below is a guess of mine").
3. **Window and t.** The trigger fires at the sample that completes the debounce; with the C1.4 order (ring push, trigger test, window append) the ring holds t and 15 earlier samples, so the window is t-15 .. t+134 as C1.5 says. The warm-up (>= 16, default 32) means t >= 32 after boot or resync, so no padding (C1.8); after a dropped window the 30-sample REARM keeps the next window past a gap (F-06 for `quiet < 16`).
4. **C1.7 / C1.10.** Only the ARMED branch fires; LOCKED persists until `trigger_release()`, REARM needs 30 consecutive samples below `lo`. The trigger is fed every sample in order in every state, so a burst of 16 samples gives the same result as 16 single calls; the "never freeze" rule has no interaction with bursts. Re-arm is reachable after a gesture that ends in a new orientation: Z-up -> X-up at sample 160 with release one sample after t, the second pulse is detected from onset 236 (S = 3) / 250 (S = 4); with release at t+135 both are detected.
5. **Edge cases.** Threshold 0 never fires and the baseline keeps running; setting 0 during REARM leaves it in REARM (`lo` = 0, `stat < 0` never true) until a non-zero threshold is set, which is acceptable. Saturation: F-05.
6. **Table.** Reproduced with a fresh implementation that does not import `trigger_ref` (`recheck.py`): tilt S3 N2 250 mg 0/60, 200 mg 4/60 (7 %), S4 N2 300 mg 28/60 (47 %), bump S3 N1 250 mg 60/60, N2 0/60, tremor 0/60; margins rest 16, tremor 122, tilt 216, bump 612 mg: all as in the table. `make test` reproduces the full table and per-gesture lines.
7. **Margin discussion.** The 216 versus 250 mg margin is stated honestly (3.1, section 4 "thin on both sides", Q1: a real quick wrist turn will exceed it). Note the weakest synthetic gestures (swipe_r 220 mg) are as low as the slow-tilt peak (216 to 228 mg), so the threshold does not separate them by construction; only real data (WP2) can.
8. **Course rules.** AI markers are present in `trigger.h`, `trigger.c`, `trigger_cli.c`, `trigger_ref.py`, `evaluate.py`, `synth.py`, `Makefile`; the 3-line `.gitignore` has none (trivial). Fixed-width types throughout `trigger.c`/`trigger.h`; no float, no malloc, no blocking in the C (`grep` clean). Floats in `synth.py`/`evaluate.py` are host-only. No register writes. No borrowed code, stated in `trigger.c`.
